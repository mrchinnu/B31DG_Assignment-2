# B31DG_Assignment-2

This project demonstrates two real time scheduling strategies which have been implemented on an ESP32 using Arduino framework as cyclic executive and a FreeRTOS based task scheduler. In the cyclic executive implementation, a function triggers with periodic ticker at a given tick interval of 1 millisecond. This is the function that’s the main scheduler which will check the current tick count (within the hyperperiod of 60 milliseconds) to know which tasks to run. Different tasks are launched depending on the modulo of the tick count tasks such as the following: generating output from digital pins, measuring frequency and frequency sums from input pins, running background monitoring work, or updating an LED indicator with the sum of frequency values for two source input pins. The cyclic executive code also includes a debounced button check routine that toggles an LED and carries out some of the monitoring processes. Tasks are launched using a particular time slot that is calculated equal in advance. However, it exploits a preemptive, priority based scheduling framework as used in the FreeRTOS version. In this part, we run separate tasks on concurrent basis in FreeRTOS’s built in scheduler. Fixed periodic rate (period from 3 to 10 milliseconds) tasks are assigned to certain core and priorities. The functionality is divided into separate functions, with two functions assigned to generate unique digital waveforms on designated pins, two others to measure the frequency on their respective input pins by some busy loop for timing, and yet another function to do continuous monitoring work. On some occasions, it would also update an LED based on a combination of the frequency readings. Additionally, the FreeRTOS implementation also ties in a watchdog timer (via 'esp_task_wdt') that observes the health of critical tasks by resetting the watchdog timer from every critical task on a regular basis to ensure that the critical task is operating within its time constraint. The button handling continues to be interrupt driven in that a falling edge is actually the trigger for the button followed by the actual triggering of an LED output and performing the work associated with monitoring, and de bounces logic is implemented to prevent activation due to spurious events.Both uses the 'B31DGMonitor' library for tracking the start and end of each job or task and it integrates the library accordingly. The execution timelines generated by this built in tracking enable us to track the actual execution schedules and help us diagnose issues such as task overrun, scheduling glitches etc. With serial output (live monitoring) or further sophistication with more advanced visualization tools it is possible to make the library’s functionality extend to even advanced real time system diagnostics.Hardware connections for the project are relatively easy. Two distinct digital inputs (available on pins 18 and 22) are used for the frequency measurement and signal outputs are connected to digital pins 26 and 32. The measured frequencies are reflected by an LED on pin 4 lighting up when the sum is greater than a certain threshold (1500 Hz), and an additional LED controlled by a user button on pin 23 is then also controlled by an LED on pin 25. By keeping implementation clean, the design highlights both scheduling techniques: the cyclic executive solution simplifies scheduling by being based on timers resulting in easy predictable task execution order while the FreeRTOS one accommodates more advanced application by ensuring better task isolation, more robust fault tolerance with watchdog supports and easier control over application scaling.
